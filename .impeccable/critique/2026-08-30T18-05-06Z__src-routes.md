## Design Specificity Verdict

**LLM assessment:** Mostly genuine, personal design — not a template. Hardcoded entity IDs (`light.kitchen_group`, `light.christmas_tree`), a real device-priority list in `useActiveMediaPlayer.ts`, Dutch UI copy, Zonneplan-tuned tariff bands, and `LightCard` rendering a bulb's *actual live RGB* as its own background are all decisions that only make sense for this specific home. Two seams break the illusion: `Vacuum.tsx` still reads literal Hakit scaffolding ("Welcome to your new Hakit project!") behind a fully-styled sidebar tile, and `ErrorPage.tsx` is an untouched, unstyled react-router-style fallback completely outside "The Night Console" language — the app's two most template-like moments are exactly its unfinished/unhappy paths.

**Deterministic scan:** `detect.mjs --json src` (58 files scanned) exited 2 with 2 findings:
1. `design-system-color` — `#404040` outside DESIGN.md's palette, `src/routes/Energy/components/EnergyChart.tsx:74` (recharts tooltip `background`). Possible false positive: plausibly an intentional chart-chrome color, not drift — but it is genuinely undocumented, so it should either be added to DESIGN.md's tokens or replaced with `neutral-800`.
2. `gray-on-color` — `text-gray-700` on `bg-blue-200`, `src/routes/Weather/utils/getWeatherIcon.tsx:76` (the snow forecast icon badge). Real contrast concern, not flagged as false positive.

The detector caught both of these; the LLM review did not surface either. In the other direction, the LLM review caught something the detector missed entirely: `src/components/atoms/Tooltip/Tooltip.tsx` builds a Tailwind class as `` text-[${getTariffColor(tariff)}] ``. Tailwind's JIT scanner requires a complete static string — a runtime-interpolated arbitrary value like this is never generated at build time, so the Energy tooltip's tariff-color text silently renders as default color. This is a real, currently-shipping bug in exactly the one place DESIGN.md calls out color as "the direct number encoding" for tariffs — worth fixing regardless of which assessment caught it.

## Overall Impression

The visual language (Assessment 8/4) is the best-executed part of this app by a wide margin — genuinely disciplined, restrained, and specific to this home. But the moments that matter most on an always-on kiosk — feedback that a tap registered, recovering from an error, anyone using it without perfect vision/motor control/full-time attention — are almost entirely unbuilt. The biggest opportunity: the gap between "beautiful when everything works" and "reassuring when something doesn't" is the single largest hole, and it hits the two highest-frequency real behaviors (toggling a light, hitting any error) hardest.

## What's Working

1. **The tariff-color system is real domain modeling.** `getTariffColor.ts`'s exact thresholds (≤0.26/≤0.30 €/kWh), the deliberate "cost ≠ alarm-red" rule, and its consistent reuse across the sidebar badge, Energy stat tiles, and chart bars is a coherent signal system built around how Dutch dynamic pricing actually behaves.
2. **`LightCard`'s live-RGB-as-background** is a distinctive, non-generic idea — the card's surface *is* the bulb's actual current color, which only makes sense because this home has color-capable bulbs (the Christmas tree, living room).
3. **Disciplined 4-item chunking**, held consistently across the sidebar, the light grid, and both Energy stat columns — a real constraint, not an accident.

## Priority Issues

**[P1] Energy tooltip's tariff color is silently dead code.**
Why it matters: `Tooltip.tsx`'s `` text-[${getTariffColor(tariff)}] `` never compiles to real CSS (Tailwind JIT can't see a runtime-interpolated arbitrary value) — the one spot DESIGN.md names color as "the direct number encoding" for tariffs currently renders as plain text color, silently.
Fix: pass the color via inline `style={{ color: getTariffColor(tariff) }}` instead of a dynamic Tailwind class.
Suggested command: `/impeccable harden`

**[P1] Zero accessibility scaffolding — not degraded, inoperable for keyboard/screen-reader users.**
Why it matters: no `aria-*`, `role`, or `tabIndex` exists anywhere in `src/`. `Card.tsx` (the base primitive under every `LightCard`/`MediaCard`) is a bare `<div onClick>` — not keyboard-focusable, not announced, no `aria-pressed` for its own on/off state. `TileButton.tsx`'s icon-only nav has no accessible name. For a household that includes non-technical family, this is the difference between "usable" and "cannot use this at all" for an entire access mode.
Fix: make `Card` a real button/role with keyboard handlers, `aria-pressed` where it toggles state, and accessible names on every `TileButton`.
Suggested command: `/impeccable audit`

**[P2] No tap feedback anywhere, contradicting DESIGN.md's own stated interaction model.**
Why it matters: DESIGN.md promises "fast (~200ms) transitions for direct tap feedback (scale)," but no `:active`/pressed-state styling exists in the codebase — the only scale transform (`TileButton`'s `isActive && 'scale-105'`) signals current route, not "tap registered." Every light/media tap waits on a real HA round-trip before anything visibly changes, which reads as unresponsive under normal network lag.
Fix: add an immediate local pressed-state (opacity/scale on `:active`) to `Card.tsx`, decoupled from the entity's actual reported state.
Suggested command: `/impeccable animate`

**[P2] Home's left column breaks the "Card is the base surface for everything" rule, and `GraphCard` uses an undocumented tone.**
Why it matters: `Home.tsx`'s left column (Time/Date/Weather/Calendar) is bare text on black with zero Card wrapper, while the right column is 100% Card-based — an unexplained two-tier structure. `GraphCard.tsx`'s `bg-slate-400 text-black` (detector-flagged, `design-system-color`) is also the lightest, loudest surface in the entire app for what should be a quiet stat tile.
Fix: either formalize the left column as a deliberate "ambient info, no chrome" tier in DESIGN.md, or wrap it in `Card` for consistency; resolve `GraphCard`'s tone against the documented `card-default`/`card-neutral` pair.
Suggested command: `/impeccable layout`

**[P3] Error states break the "calm instrument panel" promise with no recovery path.**
Why it matters: `CalendarCard.tsx` shows a raw, untranslated `{error.name}: {error.message}` in an otherwise fully-Dutch, styled app. `ErrorPage.tsx` — the app-wide fallback — has no black canvas, no Poppins, no Card, no retry button: a genuine dead end on an unattended kiosk with no keyboard.
Fix: restyle `ErrorPage` to match the system (Card, retry action); translate and soften `CalendarCard`'s error copy to match `Weather.tsx`'s pattern.
Suggested command: `/impeccable clarify`

## Persona Red Flags

**Sam (accessibility-dependent):** Total exclusion, not degraded experience — no `aria-*`/`role`/`tabIndex` anywhere means keyboard and screen-reader access don't exist at all. The `LightCard` detail modal is reachable *only* via a sustained 1000ms touch-hold with no alternate path for anyone who can't hold a precise long-press. The tariff Badge (`Sidebar.tsx`) uses green-600/white/red-500 as its *only* signal — a classic red-green colorblind confusion pair, with no icon or text per DESIGN.md's own "no icon, no text needed at this size" rule.

**Jordan / non-technical family member:** The long-press-to-modal gesture has zero visible hint it exists anywhere in the UI. Calendar dot colors (`bg-blue-300` all-day vs `bg-green-300` timed) are never explained. The Vacuum tile sits in the same polished sidebar as three finished routes and leads to literal placeholder text — reading as "the app is broken," not "not yet built."

**Family member glancing from across the room:** The clock and weather animation serve this persona well, but "is a light on" is signaled only by a subtle card-background shift plus a thin brightness-bar thumb position — for a dim or cool-toned bulb that delta may not read at a glance, in tension with the product's own "glanceable, not read closely" principle.

## Minor Observations

- `CustomLabel.tsx`'s cent formatting (`Math.round(value*100).toString().replace(/^0+/,'')`) renders an **empty label** when a tariff is exactly 0 — plausible on Dutch zero/negative dynamic-pricing days.
- `MediaCard`'s two controls have inconsistent hit areas: `BiPowerOff` gets `p-8` (~96px), `PlayPauseIcon` gets none (~56px) — same card, same interaction class, different generosity.
- `useLowBatteryNotification.tsx` toasts are `autoClose: false` — they persist indefinitely on an "always-on calm" kiosk until the device recovers, in tension with product principle #4.
- Favicon is still the default `/vite.svg` on a tab that's presumably open 24/7.
- `getWindDirectionIcon.tsx` rotates a single "up" arrow by degrees rather than a compass glyph — functional but an odd convention for a non-technical viewer.
